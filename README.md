# Kara Shift Manager — اصلاحات کنترل انتخاب پرسنل و تطبیق تاریخ

## وضعیت این بسته
این بسته یک نسخه اصلاح‌شده از برنامه دسکتاپ فعلی مبتنی بر PySide6 و Qt WebEngine است. **این بسته هنوز ایجنت هوش مصنوعی مبتنی بر Playwright نیست** و اجرای end-to-end روی حساب واقعی کارا از محیط ساخت انجام نشده است.

## اصلاحات این بسته
- جستجوی پرسنل با شناسه واقعی `TextBoxCardNo` و دکمه `ButtonSearch` مطابق HTML ارائه‌شده.
- انتخاب فقط وقتی انجام می‌شود که دقیقاً یک ردیف با کد ملی کامل تطبیق داشته باشد.
- بررسی `hf1` و تعداد انتخاب‌شده و استفاده از دکمه‌های واقعی `ButtonOk` / `ButtonOKTop`.
- انتظار زمان‌دار برای بارگذاری جدول نتایج به‌جای تأخیر ثابت پس از جست‌وجو.
- پس از انتخاب پرسنل، ابتدا بررسی می‌شود تقویم روزها از قبل ساخته شده یا نه؛ اگر ساخته نشده باشد، برنامه دکمه «نمایش روزهای شیفت» را با شناسه‌های شناخته‌شده یا متن دکمه پیدا و اجرا می‌کند. اگر دکمه در HTML قابل تشخیص نباشد، از کاربر می‌خواهد آن را دستی بزند و سپس ادامه دهد؛ دیگر بدون اجرای این مرحله مستقیماً وارد انتظار تاریخ‌ها نمی‌شود.
- فقط کنترل‌های `rpMonths_ctl00_rpDays_ctl06` تا `ctl35` بررسی می‌شوند؛ `ctl00` تا `ctl05` خانه‌های خالی `----` هستند و کاملاً نادیده گرفته می‌شوند.
- تطبیق هر ورودی `*_txtShiftName` فقط با فیلد تاریخ متناظر `*_hfFaDate` و ظرف `*_divDayITem` با همان شماره کنترل؛ عدم استفاده از حدس تاریخ از متن والد.
- جلوگیری از ارسال در صورت تاریخ تکراری، تاریخ مفقود، اختلاف مقدار واردشده یا عدم تطبیق کامل روزها.
- جلوگیری از اعلام موفقیت در صورتی که پیام موفقیت از قبل، پیش از ارسال، در صفحه وجود داشته باشد.
- تست‌های واحد برای نگاشت کدهای شیفت.
- گردش‌کار GitHub Actions برای ساخت پوشه EXE ویندوز.

## قوانین شیفت
- ص = `M921`
- ع = `M1400`
- م = `SHIFT`
- ن و خانه خالی = `OFF`
- ض و غ = خطا و توقف همان ردیف
- در کد ملی تکراری، فقط ردیف «اصلی» خودکار پردازش می‌شود؛ ردیف «دوم» دستی می‌ماند.

## اجرای محلی
```powershell
py -3.11 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m unittest discover -s tests -v
python main.py
```

## ساخت EXE در GitHub
محتویات پوشه پروژه را در ریشه مخزن قرار دهید و push کنید. سپس در GitHub > Actions، گردش‌کار `Build Kara Shift Manager (Windows)` را اجرا کنید. خروجی `KaraShiftManager-Windows` یک پوشه کامل است؛ همه محتویات آن را Extract کنید و EXE را از داخل پوشه اجرا کنید.

## محدودیت تأیید
تست‌های واحد و بررسی نحوی در محیط ساخت اجرا می‌شوند، اما این موارد جایگزین تست واقعی روی حساب کاربر نیستند. قبل از ثبت گروهی، یک نفر را انتخاب و نتیجه را در خود سامانه بررسی کنید. تا زمان تأیید واقعی این مرحله، اجرای گروهی را فعال نکنید.


### نگاشت قطعی ۳۰ روز ماه
در ماه ۳۰ روزه، برنامه دیگر برای شروع پرکردن به کشف `hfFaDate` وابسته نیست. دقیقاً ۳۰ ورودی با شناسه‌های `ctl06` تا `ctl35` را به ترتیب روزهای ۱ تا ۳۰ پر می‌کند؛ `ctl00` تا `ctl05` نادیده گرفته می‌شوند. اگر `hfFaDate` مقدار معتبر داشته باشد، فقط به‌عنوان کنترل ایمنی ماه/روز استفاده می‌شود. برنامه فقط وقتی ادامه می‌دهد که هر ۳۰ ورودی و ظرف متناظر وجود داشته باشند.
